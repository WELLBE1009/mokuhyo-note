# 目標と記録ノート（温度システム β版）

温度システムの「目標設定シート」と「週次・月次記録シート」をひとつにまとめた Web アプリです。
スマホでもパソコンでも、ブラウザで開くだけで使えます。claude.ai のアカウントは要りません。

- **本人**：目標設定シートを書く／毎週の記録をつける／振り返りを書く
- **コーチ**：担当する人のノートを見る／記録に「確認した」を付ける／ひとこと返す／1on1で一緒に書く
- **管理者**：メンバーを登録し、誰がどのノートを見られるかを決める

記録をつけるたびに、まず目標を1本の文で読み、「このまま続ける／言葉を直したい／目標を変えたい」を選ぶ流れになっています。
「直したい」が出たとき、または前回の見直しから28日・記録4回がたったときに「目標を見直す」の知らせが出ます。

## しくみ

| 置き場所 | 何をしているか | 費用 |
|---|---|---|
| GitHub Pages | 画面（このフォルダのファイル）を公開する | 無料 |
| Firebase Authentication | ログイン（Google か、メール＋パスワード） | 無料枠で足ります |
| Cloud Firestore | 目標・記録・振り返りのデータを保存する | 無料枠で足ります（50人規模） |

GitHub に置くのは画面のファイルだけです。**スタッフの目標や記録は GitHub には入りません**（Firestore に入ります）。
リポジトリが公開でも、データを読めるのはルール（`firestore.rules`）で許された本人・コーチ・管理者だけです。

## ファイル

| ファイル | 中身 |
|---|---|
| `index.html` | 画面の骨組み |
| `style.css` | 見た目 |
| `app.js` | 動き（ログイン、保存、画面の切り替え） |
| `firebase-config.js` | Firebase の接続情報（手順2で貼り付ける） |
| `firestore.rules` | 誰が何を読めるか・書けるかのルール |
| `firebase.json` | Firebase の設定（コマンドで公開する人向け。使わなくても構いません） |

`firebase-config.js` が空のままだと、保存されない「デモ表示」で動きます。`index.html` をダブルクリックすれば手元で見た目を確認できます。

## セットアップ手順（はじめの1回だけ。目安 40〜60分）

Google アカウントと GitHub アカウントが1つずつあれば進められます。

### 手順1　Firebase のプロジェクトを作る
1. https://console.firebase.google.com/ を開き、「プロジェクトを作成」。
2. 名前は例えば `wellbe-mokuhyo-note`。Google アナリティクスは「オフ」で構いません。

### 手順2　Web アプリを登録して、接続情報を貼る
1. プロジェクトの最初の画面で「</>」（ウェブ）のアイコンを押す。
2. アプリのニックネームは `mokuhyo-note`。「Firebase Hosting」のチェックは不要。
3. 表示される `const firebaseConfig = { ... }` の中身（apiKey〜appId）を、`firebase-config.js` の同じ項目に貼り付けて保存。

### 手順3　ログインの方法をオンにする
1. 左のメニュー「構築」→「Authentication」→「始める」。
2. 「ログイン方法」タブで **Google** を有効にする（サポートメールに自分のアドレスを選ぶ）。
3. 同じく **メール / パスワード** を有効にする（「メールリンク」はオフのまま）。
4. 「テンプレート」タブの右上の言語を **日本語** にする（確認メールが日本語になります）。

> メールのリンクだけでログインする方式は、無料プランでは1日5通までしか送れないため使っていません。

### 手順4　データの置き場所（Firestore）を作る
1. 「構築」→「Firestore Database」→「データベースの作成」。
2. ロケーションは **asia-northeast1（東京）**。※あとから変えられません。
3. 「本番環境モード」で作成。
4. 「ルール」タブを開き、中身をすべて消して `firestore.rules` の中身を貼り付け、「公開」。

### 手順5　管理者を登録する
1. Firestore の「データ」タブで「コレクションを開始」。
2. コレクション ID：`admins`
3. ドキュメント ID：**管理者のメールアドレス（すべて小文字）**　例：`minel@example.com`
4. フィールドは何でも構いません（例：`name` ／ 文字列 ／ `峯戸松`）。保存。
5. 管理者を増やすときは、同じように `admins` の中に文書を足します。

### 手順6　GitHub Pages で公開する
> GitHub アカウントには必ず2段階認証（Settings → Password and authentication）を設定してください。画面のファイルを書き換えられると、入力内容を盗まれるおそれがあるためです。

1. GitHub で新しいリポジトリを作る（例：`mokuhyo-note`）。
2. 「Add file」→「Upload files」で、このフォルダのファイルをすべてアップロードして「Commit changes」。
3. 「Settings」→「Pages」→ Branch を `main`、フォルダを `/ (root)` にして「Save」。
4. 数分すると `https://（GitHubのユーザー名）.github.io/mokuhyo-note/` で開けるようになります。

### 手順7　公開したURLを Firebase に登録する
1. Firebase の「Authentication」→「設定」→「承認済みドメイン」→「ドメインの追加」。
2. `（GitHubのユーザー名）.github.io` を追加。
   これをしないと、Google ログインで「このURLは登録されていません」と出ます。

### 手順8　使い始める
1. 公開したURLを開き、管理者のアドレスでログイン。
2. 「＋ メンバーを追加」で、氏名・本人のメール・コーチのメールを登録。
3. 本人とコーチにURLを伝える。
   - Gmail を使っている人は「Googleでログイン」。
   - それ以外の人は「はじめて登録」→ 届いた確認メールのリンクを押す →「確認した」。
   - **登録したメールアドレスと、ログインに使うアドレスが同じであること**が条件です。

## できること・できないこと

できること
- 本人とコーチ（と管理者）だけがその人のノートを見られる
- スマホのホーム画面に追加すれば、アプリのように開ける（ブラウザの「ホーム画面に追加」）
- コーチが複数いても、それぞれがログインして見られる

できないこと（今の作り）
- **通知は送りません。** 「記録の日です」のようなお知らせは、LINE などで別に送ってください。
- **データの自動バックアップはありません。** 無料プランでは Firestore の自動書き出しが使えません。大事な期末の前には、管理者が画面の内容を控えておくか、有料プラン（Blaze）でバックアップを設定してください。
- **電波のない場所では保存できません。**
- **書いた週の記録は、あとから本文を書き換えられません。** 付け足せるのは「確認した」「ひとこと」だけです。書き間違いの削除は管理者が行います。
- **「成長担当」は名前を書く欄だけです。** 成長担当にもノートを見せたいときは、その人のメールを「コーチのメールアドレス」に入れてください。

## 困ったとき

| 症状 | 確かめること |
|---|---|
| ログイン後「まだあなたのノートがありません」 | 管理者が登録したメールと、ログインしたメールが同じか（大文字・小文字は区別しません） |
| 「このURLはFirebaseに登録されていません」 | 手順7 |
| 管理者なのに「メンバーを追加」が出ない | 手順5のドキュメント ID が、ログインしたメールと完全に同じか（小文字で） |
| 何も表示されない | `firebase-config.js` の貼り付け漏れ。ブラウザの開発者ツールの Console を見る |
